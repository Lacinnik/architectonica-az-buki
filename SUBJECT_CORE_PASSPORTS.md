# Subject Core — паспорта реализаций

Версия документа: 1.0 · 22 сентября 2026.
Исходный срез: `7fc57decef0467cfb37a6595856b0333d9582510`.
Паспорта описывают фактические программные контракты, не присваивают канонический или эмпирический статус.

## SC-RUNTIME-001 — библиотечное ядро

| Поле | Значение |
|---|---|
| Источник | [subject_core.js](subject_core.js), владелец исходников: Lacinnik/architectonica-az-buki |
| Версия | Комментарий v1.0.0; схема snapshot `architectonica.subject-core/1.1.0`. Это разные идентификаторы |
| Назначение | Удерживать subjectId, намерение, инвариант, контекст и последовательность переходов |
| Вход | begin(intent, invariant, context); registerTransition(plate, formula, metrics, axis, note) |
| Выход | Запись перехода; snapshot с состоянием и языковым представлением |
| Хранение | Массив transitions в памяти экземпляра; встроенного постоянного хранилища нет |
| Состояния | idle → active → completed; begin начинает новый журнал |
| Q | В metrics передаёт вызывающий код; normalizeMetric приводит к диапазону 0–1. В language snapshot observedQ отдельно равен null |
| Допуск | Локальная библиотека не удостоверяет личность, внешние полномочия или исполнение |

**Известная граница:** отсутствующая метрика проходит через `Number(String(value ?? ""))` и становится 0. Поэтому текущий metrics.Q нельзя считать строгим контрактом «null до наблюдения». Этот паспорт фиксирует поведение, не исправляет его. Значение axis также задаёт вызывающий код; это не независимый вердикт.

## SC-UI-001 — браузерный Subject Core

| Поле | Значение |
|---|---|
| Источник | subject-core/index.html и assets/app.js; владелец поставки: этот репозиторий |
| Версия | Поставка закрепляется commit; отдельная версия JSON-экспорта отсутствует |
| Назначение | Карты четырёх плит, выбор Аз/Буки/Передачи, дневник, сравнение формулировок |
| Хранение | `gdeya.subject-core.diary.v1`; контейнер {version:1,items}; предел 500 |
| Выход | JSON-массив дневника без поля schema; CSV-представление |
| Q | Ручной текстовый ввод; сохраняется в metrics.Q. Не равен модельной близости resonance.similarity |
| Семантика | Модельная оценка или структурный fallback; высокий коэффициент не удостоверяет реальный возврат |
| Основание | [ACCEPTANCE.md](subject-core/ACCEPTANCE.md) описывает историческую приёмку конкретного baseline; не заменяет приёмку нового commit |

Совпадение названия с библиотекой не делает форматы совместимыми. Поставка UI содержит собранный код; соответствие другой сборке устанавливается сравнением конкретных артефактов, а не названием.

## Обмен с другими реализациями

| Источник → получатель | Текущий контракт |
|---|---|
| SC-RUNTIME-001 → Meta Core в Game-GDEYA | Vendored исходники закреплены на 7fc57de; защитный адаптер получателя и собственная проверка входа обязательны |
| SC-UI-001 → SEP или игровая сессия | Автоматический преобразователь не установлен; JSON-массив нельзя объявлять паспортом SEP |
| Игра → runtime | Прямое подключение игрового экспорта не установлено; qSim нельзя преобразовывать в наблюдаемое Q |
| Любой локальный результат → внешнее действие | Сам по себе не даёт полномочий и не удостоверяет исполнение |

[Паспорт игры, SEP и интеграции](https://github.com/Lacinnik/Game-GDEYA/blob/main/public-web/public/platform/SUBJECT_CORE_COMPATIBILITY.md).

## Правило изменения

При изменении схемы, смысла Q, хранения или приёмки обновлять паспорт. Фиксировать commit и происхождение данных. Не переносить отметку PASS между реализациями. Исправление null/0 и миграции — отдельные изменения с профильной проверкой.
